## Current product findings

- The default workbench opens the global 3D plant. Its process diagram renders the entire authored graph: 36 assets and 47 streams.
- Selecting FL1 changes the selected-asset panel and highlights FL1. It does not change the diagram's asset or stream set. There is no process-area navigator or distinct area schematic.
- The 2D view uses one fixed graph layout and generic rounded rectangles with asset IDs. It does not offer unit-specific process layouts or process equipment symbols.
- The 3D view is one full-plant scene. Asset selection changes highlighting; it does not select an area-specific scene.
- The workbench starts in synthetic replay. A read-only gateway may be configured, but no real plant endpoint or site observations are supplied in the public build.
- Engine evidence is a versioned, precomputed artifact collection. The workbench does not discover or subscribe to a fleet of CAOS engines at runtime.
- The authored graph already distinguishes extraction, stockpiling, crushing, grinding, flotation, leaching, refining, thickening, tailings and utilities. Water-bearing contributions use `water_m3_h`; not every water-bearing edge has `material: water`.

### Fresh visual-research findings: 2026-11-02

The supplied PlantCraft repository was rechecked directly. Its published suite separates Historian, Analytics, View, Alarms, Models and Documents; apps exchange published data through a shared API rather than calling each other. Its View documentation describes dashboards, diagrams and saved trends; the repository also links an interactive demo, which was inaccessible to the text-only web fetch used for this review. Therefore the repository supports PlantCraft as the requested architectural and interaction reference, but this pass does not claim a fresh visual inspection of its rendered demo. The mode specs below are OreBridge requirements derived from the user's mine-to-plant scope, not a PlantCraft copy.

The comparison is deliberately split by capability: PlantCraft for shared plant data and area-linked diagrams; SCADAvis/FUXA for data-bound SVG process screens; PrOMMiS and process-flow tools for mineral/process content and stream routing; Honeywell/MineTwin for the relationship among plant context, KPIs and spatial views. None of these references alone defines a high-quality OreBridge interface. The app must be visually reviewed against its own explicit per-mode requirements; component presence, a successful build, and a collision-free SVG do not establish visual quality.

## Data and integration boundary

The plant graph is synthetic reference data, not a surveyed or commissioned plant. Live display is enabled only for an explicitly configured read-only source. The source contract must preserve stable asset/tag identity, engineering unit, source and receipt times, quality, sequence, source name and version. Missing or invalid data remains visibly unavailable.

CAOS engine products are consumed through a versioned engine manifest and artifact adapter. Each contribution is bound to plant assets/streams and carries its source product, engine ID/version, artifact hash, units and evidence class. The browser does not silently execute arbitrary engine packages, merge incompatible units, or relabel external case data as this plant's live measurement. Existing engine-evidence artifacts remain one adapter input. New product adapters can be added without changing diagram components.

For water balance, the view uses the authored `water_m3_h` contribution on all water-bearing streams, including slurry/solution streams. It shows measured/reference/unavailable provenance per value. It reports closure only when a compatible balance model supplies a valid, declared boundary set; it never sums internal recirculation as external water input.

## Local redesign review: 2026-11-01

The initial desktop capture of the local redesign showed that the area selector could update the area heading while leaving the user on the global view. The first geometry sweep also returned “clear” with zero equipment nodes because it queried a nonexistent `.ob-node-body` class. Neither state met the acceptance criteria. The scope action now opens the area's detailed process page from the global overview, while keeping the 2D or 3D representation active when drilling down from those views. The geometry sweep now asserts the expected node count and checks both overview and 2D-plan drill-down in English and Spanish.

The 3D capture showed the area ground plane remained at the global origin, exposing a second patch of grid beside the crushing layout, and the ROM stockpile was a simple cone. The ground and grid now center and scale around the selected area, the camera fits actual mesh bounds more tightly, and the ROM terrain is a low-relief, two-ridge form. Detached status spheres were removed, process routes were thinned, and crusher profiles differ between primary and secondary units. Hovering an asset opens a data card with its identity, status, value, unit and evidence class. The schematic drawing sheet, clipped labels and a flotation boundary route that extended below its view box were also corrected.

The content review found the area detail led with short generic purpose text while the available data remained clearly synthetic/reference. Added a bilingual circuit guide for all nine areas with a graph-specific process path, engineering checks, boundary/evidence limits and an explicit illustrative-data warning. These checks explain how to read the model; they are not operating recommendations or diagnoses. A first screenshot review caught low-contrast guide heading text, which was corrected before the follow-up capture. Primary technical grounding reviewed for flowsheet stages, flotation variables and water-reclaim context includes [Metso's comminution-to-dewatering flowsheet](https://www.metso.com/globalassets/pdfs-and-other-downloads/brochure---concentrates-filtration-4863-en.pdf), [AusIMM flotation design data](https://www.ausimm.com/globalassets/insights-and-resources/minerals-processing-toolbox/flotation_data_for_design_of_process_plants-dunne_1.pdf) and [AusIMM process-water quality management](https://www.ausimm.com/publications/conference-proceedings/water-in-mining-2006/a-systematic-approach-to-water-quality-management-in-the-minerals-processing-industry/). These sources inform general process interpretation; they do not validate this authored plant graph or its rates.

Local evidence: `npm run build` passes; `npm test` passes (90 tests); `npm run check:diagram-geometry -- http://127.0.0.1:4180` covers all nine areas in English and Spanish, area drill-down, mobile overflow/scroll, per-area 3D scope and the 3D hover card.
